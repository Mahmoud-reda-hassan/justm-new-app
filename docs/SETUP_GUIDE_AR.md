# وحدة تهيئة Just-M

## التثبيت من المتصفح

1. اضبط ملف `.env` أولًا: `APP_KEY` وبيانات اتصال قاعدة البيانات `DB_*`.
2. أنشئ مفتاحًا عشوائيًا قويًا لا يقل عن 32 حرفًا، وضعه في `SETUP_TOKEN`. لا تستخدم كلمة مرور عادية ولا تشارك المفتاح.
3. افتح `/setup`، وأدخل المفتاح في النموذج. صلاحية جلسة التثبيت 15 دقيقة من آخر دخول، مع حماية CSRF وتحديد معدل المحاولات.
4. اختبر الاتصال، ثم نفّذ إنشاء الجداول والبيانات الثابتة.
5. في نموذج واحد أدخل بيانات أول مدير (والبريد الإلكتروني إلزامي)، واسم الشركة أو المؤسسة ورقم هاتفها الأول، واسم الفرع الرئيسي وعنوانه والدولة والمحافظة والمدينة، ثم اسم المخزن الأول ونوعه.
6. ينشئ النظام البيانات الجغرافية والشركة والفرع الرئيسي والمخزن والمدير في معاملة واحدة؛ إذا فشل أي جزء فلا يُنشأ المدير ولا تُعتمد بقية البيانات. اسم الشركة يُستخدم مبدئيًا اسمًا ظاهرًا للنظام.
7. بعد الإنشاء تُرسل رسالة تحقق إلى بريد المدير ويُفتح له حسابه. يجب تأكيد البريد حتى يصبح مؤهلًا لاستعادة كلمة المرور.

مثال لتوليد مفتاح مناسب من الطرفية:

```bash
php -r "echo bin2hex(random_bytes(32)), PHP_EOL;"
```

لا تدخل بيانات اتصال قاعدة البيانات أو كلمات مرورها في واجهة المتصفح؛ تُقرأ من `.env`. عند استخدام MySQL/MariaDB تحاول الواجهة إنشاء قاعدة البيانات المحددة إذا لم تكن موجودة، ولذلك يلزم منح مستخدم الاتصال صلاحية `CREATE DATABASE`. في SQLite تُنفذ التهيئة دون خطوة إنشاء قاعدة منفصلة. لا تنشئ الواجهة بيانات تجارية غير معتمدة.

## التثبيت من الطرفية (بديل)

إذا كانت قاعدة البيانات غير موجودة، يمكن استخدام:

```bash
php artisan justm:setup --create-database
```

إذا كانت موجودة بالفعل:

```bash
php artisan justm:setup
```

بعد تشغيل migrations والـ seeders، جهز بيانات الشركة والفرع والمخزن من معالج `/setup`، ثم يمكن إنشاء أول مدير من الطرفية كبديل إداري:

```bash
php artisan justm:provision-first-admin
```

يُدخل المستخدم كلمة المرور بشكل مخفي مع تأكيدها وبريدًا إلكترونيًا صالحًا. يرفض الأمر العمل إذا لم تكتمل بيانات التشغيل أو كان هناك مستخدم سابق، ويرسل رابط تأكيد البريد بعد الإنشاء. المسار المفضل للتهيئة الجديدة هو نموذج المتصفح الموحّد.

## ما الذي تنشئه الوحدة؟

- تشغيل migrations المسجلة وزرع مجموعة إدارة الوصول ونوعي المخازن الثابتين وبيانات مصر الجغرافية المرجعية (1 دولة، 7 مناطق، 27 محافظة، 516 مدينة).
- حفظ اسم الشركة كاسم ظاهر أولي للموقع في جدول `system_settings`.
- نموذج التهيئة الجديد يجمع بيانات المدير والبريد، والشركة ورقم هاتفها، والفرع الرئيسي وعنوانه، ويختار الدولة والمحافظة والمدينة من قوائم مترابطة في قاعدة البيانات، ثم يحدد المخزن الأول ونوعه.
- ربط الشركة والفرع الرئيسي بالموقع الجغرافي المختار والمخزن والمدير في معاملة واحدة. البيانات الجغرافية المرجعية تُزرع مسبقًا بواسطة Seeder قابل لإعادة التشغيل، ولا تُنشأ من نص حر داخل معالج التهيئة.
- إنشاء أول مدير مرة واحدة فقط وربطه بالمجموعة المحدودة المذكورة، ثم إرسال رسالة تحقق البريد.

## الأمان والإغلاق

- مفتاح الواجهة يأتي من `SETUP_TOKEN` ولا يوضع في الرابط أو قاعدة البيانات.
- جميع عمليات التثبيت POST ومحمية بـ CSRF، مع تحديد معدل المحاولات.
- جلسة التثبيت مؤقتة، وتُرفض العمليات بعد 15 دقيقة.
- لا تُغلق الواجهة بمجرد وجود مستخدم؛ تظل متاحة بمفتاح التهيئة المؤقت لاستكمال بيانات التشغيل الناقصة في تثبيت قائم. تُغلق نهائيًا عند اجتماع وجود مستخدم واحد على الأقل واكتمال اسم الموقع والدولة والمحافظة والمدينة والشركة والفرع الرئيسي والمخزن.
- إذا كانت هناك شركة أو فروع أو مخازن موجودة مسبقًا، يرفض معالج البيانات الأولية إنشاء مجموعة تأسيس مكررة؛ تتم إدارة البيانات الموجودة لاحقًا من شاشات الوحدة.
- لا يوجد مسار عام لإعادة إنشاء المدير أو ترقية حساب قائم.
- كلمة المرور لا تُسجل ولا تُخزن كنص صريح.
- البريد الإلكتروني للمدير الأول إلزامي وفريد، ويظل غير موثق حتى فتح رابط تحقق موقّع يصل إلى البريد.
- لا يُرسل رابط إعادة تعيين كلمة المرور إلا لحساب نشط وبريد موثق. يُتاح للمستخدم تحديث بريد حسابه بعد إدخال كلمة مروره الحالية، ثم يُطلب تأكيد البريد الجديد.
- يجب ضبط SMTP حقيقي في الإنتاج؛ قيمة `MAIL_MAILER=log` مخصصة للتطوير ولا ترسل رسائل إلى المستخدم.
- لا تحذف الوحدة بيانات موجودة ولا تنشئ حسابًا افتراضيًا أو صلاحيات شاملة.
- لا تشغّل التهيئة على قاعدة إنتاج أو بيانات فعلية دون مراجعة وموافقة صريحة.

## الاختبارات

```bash
php artisan test --filter=Setup
```

تغطي الاختبارات حماية المفتاح، صلاحية الجلسة، الاتصال، تشغيل migrations والبيانات الثابتة، إنشاء الهرمية الجغرافية والتجارية، التهيئة الموحّدة للمدير والمؤسسة، تحقق البريد، تحديث بريد الحساب، ومنع استعادة كلمة المرور قبل توثيق البريد.


## إعداد البريد الإلكتروني للتحقق واستعادة كلمة المرور

في بيئة الإنتاج يجب ضبط SMTP في ملف `.env` قبل إنشاء المدير الأول:

```dotenv
MAIL_MAILER=smtp
MAIL_SCHEME=smtp
MAIL_HOST=اسم-خادم-SMTP
MAIL_PORT=587
MAIL_USERNAME=اسم-المستخدم
MAIL_PASSWORD=كلمة-مرور-SMTP
MAIL_FROM_ADDRESS=عنوان-مرسل-حقيقي
MAIL_FROM_NAME="${APP_NAME}"
```

استخدم بيانات مزود البريد الفعلية وإعدادات المنفذ والتشفير التي يحددها. لا تضع كلمة مرور البريد في Git أو التوثيق. بعد تعديل البيئة امسح إعدادات Laravel المخبأة. إذا بقي `MAIL_MAILER=log` فستُكتب الرسائل في السجل ولن تصل إلى صندوق البريد.

## إعداد الاستضافة الحالية (IIS / Plesk)

- اضبط إصدار PHP الخاص بالموقع والطرفية/Composer على PHP 8.4 أو إصدار متوافق مع Laravel 13؛ لا يكفي ضبط إصدار الموقع إذا كان Composer يعمل بإصدار PHP أقدم.
- اجعل Document Root يشير إلى مجلد `public` داخل المشروع، وليس جذر المستودع.
- نفّذ `composer install --no-dev --optimize-autoloader` بعد ضبط PHP الصحيح، وتأكد من وجود `vendor/autoload.php`.
- أنشئ `APP_KEY` باستخدام `php artisan key:generate` أو مفتاح Laravel صالحًا، ولا تضع المفتاح في Git أو تشاركه. لا تغيّر المفتاح بعد بدء استخدام بيانات مشفرة.
- استخدم `APP_ENV=production` و`APP_DEBUG=false` و`APP_URL` الصحيح للموقع.
- اضبط `APP_CIPHER=AES-256-CBC` إذا كان هذا هو cipher المعتمد في إعداد التطبيق، وتأكد أن المفتاح بطول وصيغة متوافقين معه.
- اضبط `SETUP_TOKEN` بقيمة عشوائية قوية لا تقل عن 32 حرفًا. بعد اكتمال التهيئة، لا تترك السر مكشوفًا أو متداولًا.
- بعد تغيير إعدادات البيئة، امسح ملف الإعدادات المخبأ عبر `php artisan config:clear` أو احذف cache القديم بالطريقة الآمنة المناسبة للاستضافة، ثم أعد بناءه عند الحاجة.
- امنح PHP صلاحية الكتابة على `storage` و`bootstrap/cache`.
- لا ترفع ملف `.env` إلى GitHub، ولا تنسخ أسرار بيئة إلى التوثيق أو سجلات الأخطاء.

هذه ملاحظات تشغيلية مبنية على مسار إعداد بيئة الاختبار. افحص إصدار PHP الفعلي وصلاحيات المجلدات وإعدادات Plesk قبل تكرار الأوامر، ولا تنفذها على قاعدة إنتاج دون اعتماد.
