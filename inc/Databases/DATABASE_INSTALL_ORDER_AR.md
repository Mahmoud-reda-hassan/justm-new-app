# ترتيب إنشاء قاعدة بيانات Just-M

## الخيار الأول: ملف تثبيت موحد

استخدم `JUSTM_DATABASE_INSTALL.sql` من جذر المشروع على قاعدة اختبار فارغة. ينشئ قاعدة `cptest` ثم الجداول والبيانات المرجعية والعلاقات المرفقة.

## الخيار الثاني: ملفات منفصلة

بعد إنشاء قاعدة البيانات واختيارها في phpMyAdmin:

1. `inc/Databases/createDatabase.sql` — إنشاء الجداول والبيانات المرجعية. لا ينشئ قاعدة بيانات بنفسه.
2. `inc/Databases/createRelations.sql` — إضافة علاقات المفاتيح الخارجية القديمة. يشغّل مرة واحدة بعد إنشاء الجداول.
3. `inc/Databases/migrations/PHASE15_ACCOUNTING_SCHEMA_ALIGNMENT.sql` — مواءمة أعمدة ربط القيود وتكلفة سطر البيع ومراجع حركة المخزون. السكربت يستخدم `IF NOT EXISTS` للإضافات.
4. `inc/Databases/migrations/PHASE16_SUPPLIER_PAYMENT_MIXED_ALLOCATION.sql` — إنشاء سجل تفصيلي لتوزيع دفعات الموردين بين فواتير الشراء والمقدم غير المخصص.
5. `inc/Databases/seeds/CHART_OF_ACCOUNTS_SEED.sql` — إدخال دليل الحسابات وربط الحسابات النظامية المعروفة.

## إعدادات لا تُنشأ بقيم افتراضية

- `cash_boxes`: ربط كل صندوق بحساب أستاذ وفرع حقيقي.
- `payment_method_accounts`: ربط كل طريقة دفع بحسابها الصحيح في كل فرع.
- الأرصدة الافتتاحية والحركات التاريخية: لا يتم إنشاؤها تلقائيًا.
- لا تُعبأ تكلفة تاريخية مفقودة في `order_product.COST_PRICE` من تكلفة الصنف الحالية.

## تنبيه

نفّذ على قاعدة اختبار بعد أخذ نسخة احتياطية. نجاح إنشاء الجداول لا يثبت صحة دورة البيع أو التحصيل أو المرتجع؛ يجب تنفيذ اختبارات التكامل قبل الإنتاج. لا تحذف الجداول المالية القديمة أثناء مرحلة الانتقال.
